# API conventions (`@sisig/api`)

These rules apply to every RPC, Edge Function and client hook that the apps
(mobile and admin) call through `packages/api`. Database rules (migrations,
RLS, `SECURITY DEFINER`) are in [supabase/CONVENTIONS.md](../../supabase/CONVENTIONS.md).

## RPC naming

- RPCs are `public` functions named `verb_noun` in snake_case:
  `redeem_reward`, `post_points`, `list_point_history`. Predicates are `is_*`
  (`is_staff`).
- Arguments are prefixed `p_` (`p_reward_id`, `p_idempotency_key`).
- Points, redemptions and orders change only through RPCs or Edge Functions,
  never through direct table writes from the client.

## Idempotency keys

- Every write RPC that must not run twice takes `p_idempotency_key uuid`.
- The client creates the key once per **user intent** (for example one tap on
  "Redeem") with `crypto.randomUUID()` (`expo-crypto` on mobile), and keeps it
  for the life of that intent.
- A retry of the same intent (network failure, app restart, double tap) sends
  the **same** key. A new intent gets a new key.
- The server stores the key with a unique constraint (as `points_ledger` and
  `reward_redemptions` do) and returns the original result when it sees the key
  again with the same payload. The same key with a different payload raises
  `IDEMPOTENCY_CONFLICT`.

## Pagination

- Lists use keyset pagination on `(created_at, id)`, newest first:
  `order by created_at desc, id desc`.
- The next page is requested with the last row's pair:
  `where (created_at, id) < (p_cursor_created_at, p_cursor_id)`, plus
  `p_limit`. Back it with an index on `(…, created_at desc, id desc)`.
- No `offset` pagination: it skips or repeats rows while new rows arrive.
- The client treats the cursor as opaque and passes it back unchanged.

## Timestamps

- Columns are `timestamp with time zone`. RPCs and Edge Functions send and
  accept ISO 8601 strings in UTC (`2026-11-06T23:00:00.000Z`).
- The client converts to local time only for display. Business-day logic
  (store hours, daily caps) uses the store's `timezone` on the server.

## Input and output schemas (zod)

- Each new RPC or Edge Function gets a zod schema for its input and its output,
  next to its hook in `packages/api/src`. Parse the input before the call and
  the output after it, so a schema change fails loudly in one place.
- zod is **not a dependency yet**. The first ticket that adds a typed RPC
  (LOY-01) adds `zod` to `packages/api` and follows this rule. Until then,
  `database.types.ts` (generated by `pnpm db:types`) is the only type source.

## Query keys

- All TanStack Query keys come from the `keys` factory in
  [`src/query-keys.ts`](./src/query-keys.ts) (PLAT-03). Never inline a key array.
- Add a domain as `keys.<domain>.all()` plus narrower keys under it, and
  invalidate by prefix (`keys.loyalty.all()`).
- Only keys on `persistedQueryKeyPrefixes` are written to disk. Never add
  personal data (points, profile, orders) to that list.
- Expose each query as `xxxQueryOptions(client)` plus a thin `useXxx` hook (see
  `src/hooks/useMenu.ts`). Mutations never retry automatically.

## Errors

Raw Postgres or Edge Function messages never reach the UI. Every query and
mutation throws `normalizeError(error)` (or `await normalizeErrorAsync(error)`
for `client.functions.invoke`). The result is always an `AppError` with a fixed,
user-safe `message` and a stable `code`.

### Domain error codes

Business-rule failures are **domain errors**. Each has one stable code, one
custom SQLSTATE, an i18n copy key and English fallback copy:

| Code                   | SQLSTATE | Copy key                      | Edge Function status |
| ---------------------- | -------- | ----------------------------- | -------------------- |
| `INSUFFICIENT_POINTS`  | `SS001`  | `errors.insufficient_points`  | 422                  |
| `REWARD_INACTIVE`      | `SS002`  | `errors.reward_inactive`      | 422                  |
| `OUT_OF_STOCK`         | `SS003`  | `errors.out_of_stock`         | 422                  |
| `OFFER_NOT_ELIGIBLE`   | `SS004`  | `errors.offer_not_eligible`   | 422                  |
| `OFFER_CAP_REACHED`    | `SS005`  | `errors.offer_cap_reached`    | 422                  |
| `OFFER_LIMIT_REACHED`  | `SS006`  | `errors.offer_limit_reached`  | 422                  |
| `CLAIM_EXPIRED`        | `SS007`  | `errors.claim_expired`        | 422                  |
| `ALREADY_REDEEMED`     | `SS008`  | `errors.already_redeemed`     | 409                  |
| `IDEMPOTENCY_CONFLICT` | `SS009`  | `errors.idempotency_conflict` | 409                  |
| `RATE_LIMITED`         | `SS010`  | `errors.rate_limited`         | 429                  |
| `STORE_CLOSED`         | `SS011`  | `errors.store_closed`         | 422                  |
| `AUTH_REAUTH_REQUIRED` | `SS012`  | `errors.auth_reauth_required` | 401                  |
| `NEGATIVE_BALANCE`     | `SS013`  | `errors.negative_balance`     | 422                  |

The English fallback strings are in `DOMAIN_ERRORS` in
[`src/domain-errors.ts`](./src/domain-errors.ts).

### Raising from SQL

SQL functions raise domain errors only through `private.raise_app_error`:

```sql
perform private.raise_app_error(
  'INSUFFICIENT_POINTS',
  jsonb_build_object('required', v_cost, 'balance', v_balance)
);
```

It raises with `errcode` = the code's SQLSTATE, `message` = the code, and
`hint` = `{"code": "<CODE>", "context": {...}}` as JSON text. PostgREST
returns that as HTTP 400 with `{ code, message, details, hint }`.

Why one custom SQLSTATE per code, plus a JSON hint:

- The SQLSTATE alone identifies the error, so pgTAP can assert it with
  `throws_ok(sql, 'SS001', ...)` and the client never parses text to decide.
- Class `SS` is not used by Postgres or PostgREST (PostgREST treats `PT…` and
  `PGRST…` specially), so no built-in error can be mistaken for a domain error.
- The hint carries only the optional `context`. If the hint is missing or bad,
  the client still maps the error and uses an empty context.

Rules:

- `context` holds safe, non-personal primitives only (numbers, short ids,
  booleans). The client drops nested values.
- `private` is not exposed to API roles, so callers are `SECURITY DEFINER`
  functions (they run as the owner). Unknown codes fail with `22023`.
- Permission and not-found failures keep their standard SQLSTATEs (`42501`,
  `P0002`), which map to `PERMISSION_DENIED` and `NOT_FOUND`.

### Raising from Edge Functions

Use `domainError(code)` from `supabase/functions/_shared/errors.ts`. It returns
the standard envelope `{ "error": { "code": "RATE_LIMITED", "message": "..." } }`
with the status in the table. Domain codes are UPPER_SNAKE; the older
transport codes (`bad_request`, `unauthorized`, ...) stay lower_snake. The
client reads the body with `normalizeErrorAsync`.

### Handling in the client

```ts
import { isDomainError, normalizeError } from '@sisig/api';

const { error } = await supabase.rpc('redeem_reward', args);
if (error) throw normalizeError(error);

// In the UI:
if (isDomainError(err, 'INSUFFICIENT_POINTS')) {
  // err.copyKey === 'errors.insufficient_points', err.context.required, ...
}
showToast(err.message); // fixed English fallback until PLAT-09 adds i18n
```

- `DomainError` extends `AppError` and adds `copyKey` and `context`.
- Until PLAT-09 adds an i18n library, show `err.message` (the English fallback).
  PLAT-09 looks up `err.copyKey` instead.
- Domain errors are never retried automatically, `RATE_LIMITED` included.

### Adding a code

Codes are append-only: never rename one or reuse a SQLSTATE. To add one:

1. Add it to `DOMAIN_ERRORS` in `src/domain-errors.ts` with the next SQLSTATE,
   a copy key `errors.<code_lowercase>` and fallback copy.
2. Add a new migration that runs `create or replace function private.app_error_catalog()`
   with the full list. Never edit the old migration.
3. Add it to `DOMAIN_ERROR_CODES` and `DOMAIN_ERROR_STATUS` in
   `supabase/functions/_shared/errors.ts`.
4. Add a row to the table above.

`src/error-codes-drift.test.ts` fails until steps 1 to 3 agree. It reads the
latest migration that defines `private.app_error_catalog()`, so it runs without
a database. `supabase/tests/database/12_app_errors.sql` checks that each code
really raises its SQLSTATE.

### Sample RPC

`public.raise_sample_error()` always raises `INSUFFICIENT_POINTS`. It exists
only to prove this contract end to end (DATA-13). Remove it in a new migration
once LOY-01 ships a real caller, then regenerate `database.types.ts`.
